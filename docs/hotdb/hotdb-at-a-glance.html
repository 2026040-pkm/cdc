    04칸별 연관관계 — 자세히

    표 안의 컬럼까지 그렸습니다. PK = 이 표의 열쇠, FK = 다른 표를 가리키는 컬럼, 선은 화살표 쪽이 부모입니다.

    TSDB field data — 장비 ◀ 태그 ◀ 이력 세 표

    이력 행에는 장비 id 가 없고 tag_key 숫자만 있습니다. 태그 등록부를 거쳐야 어느 장비 · 어느 구역인지 압니다.

    FK (자식 → 부모)CDC 로 옮김 (라우트)SAP 로 보냄같은 키 (FK 없음)PK 기본키 · FK 외래키 · 오른쪽 글자 = 타입 또는 값 출처

    RDB field data — 장비 ◀ 현재 상태 ◀ 변경 이력 · 장비 ◀ 스캔 ◀ 실적 · 산출물

    판별 모듈마다 같은 다섯 표(svc_mch · asm · oft · pnt). 실적과 산출물은 반드시 스캔에 매달립니다 — 부모 없는 실적은 들어가지 않습니다.

    FK (자식 → 부모)CDC 로 옮김 (라우트)SAP 로 보냄같은 키 (FK 없음)PK 기본키 · FK 외래키 · 오른쪽 글자 = 타입 또는 값 출처

    SAP 쪽 새 표 — tsdb → RDB → SAP 로 컬럼이 옮겨 가는 길

    SAP 에 새로 만드는 표는 zhotdb_actual_result 하나. RDB 의 actual_result 컬럼이 그대로 옮겨 가고, 같은 실적 · 같은 판정은 한 번만 적힙니다.

    FK (자식 → 부모)CDC 로 옮김 (라우트)SAP 로 보냄같은 키 (FK 없음)PK 기본키 · FK 외래키 · 오른쪽 글자 = 타입 또는 값 출처

    05전체 스키마 지도

    용어종류뜻이 문서에서
    Hot DBDB현장 · 레거시 데이터를 모아 두는 PostgreSQL 한 대네 칸 + 운영 칸
    TSDB · tsdb칸 · 스키마Time-Series DB. 시간순 원본장비 데이터 그대로

    CDC약어Change Data Capture. DB 에 바뀐 줄을 바로 알아채기TSDB → 판별 모듈, RDB → RFC Service
    폴링방식정해진 주기마다 가서 바뀐 것만 읽기SAP · Oracle 레거시
    MQTT Agent서비스장비 MQTT 메시지를 태그로 바꾸는 곳 (ISL4 Agent)현장 데이터 입구
    HotDB Provider서비스태그를 TSDB 에 넣는 곳이번 범위 밖 — 시험에선 발행기가 대신
    실적 판별 모듈서비스가공 · 조립 · 의장 · 도장 실적 판별자기 구역 장비만 RDB 로
    RFC Service · DB Agent서비스그림의 O-8 · O-6SAP 왕복 · Oracle 복사
    PK · FK약어Primary Key 기본키 · Foreign Key 외래키이 줄을 찾는 열쇠 · 다른 표의 줄을 가리키는 컬럼
