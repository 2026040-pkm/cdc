    PG 하나에 레거시 · 서비스 · 필드 데이터 세 영역을 준비했습니다

    PostgreSQL 17 + TimescaleDB + logical WAL 인스턴스 하나를 세 영역(스키마)으로 나누고, 영역마다 쓰는 주체 하나에만 쓰기 권한을 줬습니다. svc 영역만 CDC 로 RFC 모듈을 거쳐 우리가 지정한 SAP 스키마로 나갑니다. 이 문서는 2026-09-30 까지 한 작업, 컨테이너에서 확인한 결과, 남은 결정을 정리합니다.

    로컬 기동 · 검증 완료 src/hotdb-tsdb PG 17.11 · TimescaleDB 2.29.2 미확정: 보관 정책 · 레거시 DDL 변환

    권한을 "앞으로 만들 표" 에도 거는 방법

    표마다 GRANT 하지 않고 ALTER DEFAULT PRIVILEGES 로 걸었습니다. 관리자(postgres)가 만든 표와 svc_app 이 svc 에 만든 표 모두 자동으로 권한이 붙습니다. 다른 계정이 DDL 을 돌리게 되면 그 계정용 기본 권한을 한 줄 더 추가해야 합니다.

    결정 · 2026-09-30 — Hot DB Provider 는 RDB 에 저장하지 않습니다

    Provider 는 tsdb 이력만 씁니다. 최신값 · 스캔 · 실적 · 산출물 같은 RDB 행은 권역별 서비스만 svc 에 저장합니다. 필드 데이터가 필요하면 서비스가 tsdb 를 읽어 쓰거나, 가공한 결과를 svc 에 저장합니다. 그래서 hotdb_provider 계정에는 legacy · svc 권한이 없고, svc_app 은 tsdb 를 읽기만 합니다.

    ADR-01 · CDC 경계를 스키마로 긋는다

    배경
    svc 는 서비스가 표를 계속 추가하고, tsdb 는 청크가 6시간 · 1일마다 새로 생깁니다.
    결정
    CREATE PUBLICATION svc_cdc_pub FOR TABLES IN SCHEMA svc. 슬롯은 만들지 않고 RFC Service 가 첫 접속 때 pgoutput 으로 만듭니다.
    대가
    svc 안의 임시 · 작업용 표도 나갑니다. 그런 표는 svc 가 아닌 별도 스키마에 둬야 합니다.
    재검토
    svc 안에 CDC 제외 표가 2개 이상 필요해지면 FOR TABLE 열거로 바꿉니다.

    WAL 관련 설정

    설정값이유
    wal_levellogicalsvc → RFC 모듈 → SAP 지정 스키마 CDC. 기본 replica 로는 논리 디코딩 불가
    max_wal_senders / max_replication_slots10 / 10CDC 소비자 + standby 여유
    max_slot_wal_keep_size10GB기본 -1(무제한)이면 소비자가 멈춘 슬롯이 디스크를 채움. 넘으면 슬롯 무효화 → 재스냅샷이 디스크 고갈보다 낫다
    wal_sender_timeout5min적재에 밀린 CDC 클라이언트를 바로 끊지 않음 (embedded-cdc 실측 근거)3
    max_worker_processes16기본 8 이면 timescaledb.max_background_workers=16 이 실제로는 8 로 묶임

    압축은 WAL 을 한꺼번에 만듭니다

    압축은 메타데이터 변경이 아니라 원본 청크를 읽어 압축 청크에 쓰는 DML 입니다. 기본 정책이면 status 는 6시간마다, 나머지는 하루마다 WAL 이 몰립니다. 반대로 보관 정리(drop_chunks)는 DROP TABLE 이라 WAL 이 거의 없습니다.
